# Compute phrasing in a Python backend

Comma-level phrasing of the performed text is computed by a FastAPI service from the playback projection, the lyric source and a per-piece overrides file, and the viewer fetches the result instead of importing `viewerModel.json` for display. Each phrase carries an evidence status (`confirmed`, `variant`, `inferred`) and its evidence, so inferred breaks stay visible and traceable. This departs from the serverless direction of ADR-0014 and ADR-0015 only for the playback and reading views: the conversion core and the score-review loop still run entirely in the browser and still read the playback projection directly. The cost is that the single-file build can no longer be opened by double-clicking; the viewer now needs the backend running.
